## 2. Применённые фиксы

### Коммит `2b27d72` — «Audit fixes: single-owner commit, control-msg collisions, bulk NaN guard»

| ID | Проблема | Фикс |
|---|---|---|
| **H1** | msg_id параметрического апдейта, совпадающий с `0xA0/0xA2/0xA5`, перехватывался как PING/SYNC_CONFIG/SAVE_CONFIG (потеря параметра, NVS-спам) | `msg_handler.c`: bulk-континуация проверяется до control-сообщений; control-сообщения требуют `payload_len == 1`. `serial_server.c`: тот же guard для PING. UI `getNextMsgId()` пропускает зарезервированные ID. |
| **H2** | `dsp_param_commit()` из serial-задачи (bulk) гонялся с commit'ом аудио-задачи: запись в буфер, который читается, double-swap | commit — только из аудио-задачи; из `apply_bulk` убран прямой вызов (осталась нотификация). |
| **H5** | bulk-блоб с NaN/Inf-коэффициентами (CRC можно пересчитать) навсегда отравлял состояния фильтров | пост-валидация `isfinite` по всем biquad-коэффициентам/гейнам/drift + диапазоны gain, зеркалящие per-param путь. |
| **M5** | UB: каст `float→uint32` в `BLE_PARAM_DELAY` для значений вне `[0, UINT32_MAX]` | проверка `isfinite && >= 0 && <= MAX_DELAY_SAMPLES` до каста. |
| **M1** | после авто-реконнекта ping/pong больше не перезапускался — устройство не мониторилось | `handleDisconnection` вызывает `startPingPongRef.current()` после переоткрытия порта (ref — против круговой зависимости useCallback). |
| **M3** | `applyDeviceConfig` без `try/finally` — исключение подписчика навсегда глушило live-стриминг | флаг сбрасывается в `finally`. |
| **L1** | мёртвый код FW | удалены `dsp_param_has_pending`, `dsp_param_set_sample_rate`, `msg_handler_read_telemetry`, `serial_frame_validate` (+ объявления в заголовках). |

### LOW

- `decodeStatusMessage`/`decodeDeviceInfo` (`param-decoder.ts:18-55`) — никем не
  используются (ACK-парсинг дублируется в `useWebSerial.ts`).

- `key={i}` в `PresetManager.tsx:236`; утечка `mousemove/mouseup` в
  `SerialConsole.tsx:37-51`; `e.repeat` в `useKeyboardShortcuts.ts`.
- `nvs_save_timer_cb` — «таймер», который больше не создаётся (`main.c`).
- Дублирование кода (см. ниже).

## 4. Дублирование кода (по результатам субагента)

- **Высокий риск:** shadow EQ-параметры закопи-пастены 6+ раз
  (`binary-encoder.ts:116-135,155-174,255-274` + `binary-decoder.ts:180-196,203-218,247-263` +
  типы `dsp.ts`/`esp32.ts`). Изменение 16-байтного блока — 4-6 мест.
- **Средний:** `input-slice`/`output-slice`/`room-eq-slice` — три копии паттерна
  «изменить полосу + зеркалить на связанные каналы»; три графика АЧХ
  (FrequencyResponseGraph, AllChannelsResponseChart, RoomEQChart); `crossoverResponse`
  ≈ `crossoverComplexResponse` в `frequency-response.ts`; 3 копии log-интерполяции
  (`auto-eq.ts:193-228`, `RoomEQChart.tsx:388-406`).
- **Чисто:** CRC-32, biquad-коэффициенты, crossover-стадии, `dbToLinear` — единые источники.

## 5. Пробелы в тестах

Покрыты только `binary-encoder` и `biquad`. Рекомендуется добавить unit-тесты:
- декодер `binary-decoder` (round-trip с encoder, `crc==0` legacy, version/magic mismatch);
- `checksum.ts` против известных векторов;
- retry-логика `useWebSerial` (fake timers: 3 ретрая, ACK-очистка, ошибка записи) — ✅ добавлено `tests/hooks/useWebSerial.test.tsx` (6 тестов: H4-бюджет ретраев, H3-коллизии сигнатур);
- слайсы (diff, link-зеркалирование, `applyDeviceConfig` с исключением);
- протокольные зеркала: каждый новый `BLE_PARAM_*` имеет энкодер/декодер/валидацию длины.
