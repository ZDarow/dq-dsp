# DSP: математика и алгоритмы

Все расчёты в `shared/dsp/dsp_param_update.c` (порт `dq-dsp-ui/src/dsp/*.ts`).
Формат коэффициентов — **negated-a конвенция**: `a1`/`a2` в `biquad_coeffs_t`
уже отрицательные, поэтому внутренний цикл биквада — только сложения.

## 1. Биквад — Direct Form II Transposed

Разностное уравнение (порядок применения на каждый сэмпл):

```
y[n] = b0·x[n] + z1
z1   = b1·x[n] + a1·y[n] + z2
z2   = b2·x[n] + a2·y[n]
```

Где `z1`, `z2` — состояния (`biquad_state_t`). DF-IIT численно стабильнее для
float32, чем DF-I: ошибки округления не накапливаются по `y`.

**Почему состояния не обнуляются при смене коэффициентов**: фильтр в DF-IIT
плавно «морфирует» — переходные состояния сходят на ноль за несколько сэмплов
без кликов. Сброс состояний дал бы щелчок.

## 2. Audio EQ Cookbook (Robert Bristow-Johnson)

Исходные величины:

```
ω0 = 2π·f / Fs          (нормализованная частота)
α  = sin(ω0) / (2·Q)
A  = 10^(G/40)          (√ линейного усиления от G дБ)
```

| Тип | b0 | b1 | b2 | a0 | a1 | a2 |
|---|---|---|---|---|---|---|
| Peaking | 1 + α·A | −2·cos | 1 − α·A | 1 + α/A | −2·cos | 1 − α/A |
| Low shelf | A·((A+1) − (A−1)·cos + 2√A·α) | 2A·((A−1) − (A+1)·cos) | A·((A+1) − (A−1)·cos − 2√A·α) | (A+1) + (A−1)·cos + 2√A·α | −2·((A−1) + (A+1)·cos) | (A+1) + (A−1)·cos − 2√A·α |
| High shelf | A·((A+1) + (A−1)·cos + 2√A·α) | −2A·((A−1) + (A+1)·cos) | A·((A+1) + (A−1)·cos − 2√A·α) | (A+1) − (A−1)·cos + 2√A·α | 2·((A−1) − (A+1)·cos) | (A+1) − (A−1)·cos − 2√A·α |
| Low pass | (1−cos)/2 | 1−cos | (1−cos)/2 | 1+α | −2·cos | 1−α |
| High pass | (1+cos)/2 | −(1+cos) | (1+cos)/2 | 1+α | −2·cos | 1−α |
| Band pass | α | 0 | −α | 1+α | −2·cos | 1−α |
| Notch | 1 | −2·cos | 1 | 1+α | −2·cos | 1−α |
| All pass | 1−α | −2·cos | 1+α | 1+α | −2·cos | 1−α |

где `cos = cos(ω0)`. После выбора ветки — нормализация на `a0` и отрицание `a1,a2`:

```
b0 = b0/a0 ; b1 = b1/a0 ; b2 = b2/a0 ; a1 = −a1/a0 ; a2 = −a2/a0
```

Unknown/identity-тип → `{1,0,0,0,0}` (прозрачный проход).

**Recalc-условие** (`recalc_input_eq_band` и аналоги): полоса считается
«прозрачной», если `!enabled || freq ≤ 0 || Q ≤ 0`.

## 3. Кроссовер (`calc_crossover_stages`)

Ключевое: значение slope-байта — это **число каскадов биквадов**, не dB/oct.
`BLE_XO_SLOPE_12=1, 24=2, 48=4`. Некорректное значение принудительно
редуцируется к 12 dB/oct (защита OOB в аудио-задаче).

### Butterworth

`order = stages·2` (1→2-й, 2→4-й, 4→8-й порядок). Q каждого каскада:

```
Q_k = 1 / (2·cos(π·(2k+1) / (2·order))),   k = 0..stages−1
```

Для 2-го порядка (1 каскад): `Q = 1/(2·cos(π/4)) ≈ 0.7071`.
Каждый каскад — обычный HP/LP биквад на частоте `f` с этим Q.

### Linkwitz-Riley

LR = «возведённый в квадрат» Butterworth (два одинаковых BW-каскада):

| Slope | Каскады | Реализация |
|---|---|---|
| LR12 (1) | 1 | один биквад с `Q = 0.5` (это и есть квадрат BW1, 6 dB/oct × 2) |
| LR24 (2) | 2 | два BW2-каскада, каждый `Q ≈ 0.7071` |
| LR48 (4) | 4 | два BW4-каскада ×2 (BW-стадии: `butterworth_q(4, k)`, затем дубликаты) |

Псевдокод LR:

```
bw_order = stages / 2            # 1, 1, 2
bw_stages = max(bw_order / 2, 1) # 1, 1, 1  ← нет: см. код
```

Точная логика из кода: для `stages == 1` — один биквад Q=0.5; иначе
`bw_order = stages` (2→2, 4→4), `bw_stages = bw_order/2` (2→1, 4→2) — сначала
`bw_stages` BW-каскадов с `butterworth_q(bw_order, k)`, затем их дубликаты.

Математическое свойство LR: на частоте кроссовера HP и LP **синфазны** и
обедают на −6 dB, сумма = 0 dB — идеальный flat-ответ через кроссовер.

## 4. ASRC — дробный ресемплер с линейной интерполяцией

Проблема: USB-хосты дают 48.000 ± ppm, I2S-кристалл платы — тоже 48.000 ± ppm;
это два независимых тактовых источника.

Решение — не дроп/дубль целых сэмплов, а **ресамплинг с дробным фазовым
аккумулятором** (избегает кликов):

```
state: phase (float), prev, cur (последние два входных сэмпла)

на каждый выходной сэмпл:
  пока phase ≥ 1.0:
      prev = cur; cur = следующий входной сэмпл; phase -= 1.0
  t = phase
  out = prev + t·(cur − prev)        # линейная интерполяция
  phase += ratio                     # ratio ≈ 1.0 ± ppm·1e-6
```

`ratio > 1.0` — потреблять вход быстрее (USB-часы быстрее, буфер полнится);
`ratio < 1.0` — медленнее (I2S быстрее, буфер уходит).

## 5. PI-компенсатор дрейфа (`drift_compensation_cb`, каждые 100 мс)

```
error    = fill − target            # fill = 1 − free/192КБ, target = 0.5
integral += error                   # анти-windup: |integral| ≤ max_ppm/ki
correction = kp·error·100 + ki·integral
correction = clamp(correction, ±drift_max_ppm)
ratio      = 1 + correction/1e6
```

- Kp=0.3, Ki=0.05, target=0.5, max_ppm=200 — дефолты; тюнятся из UI
  (`BLE_BLOCK_SYSTEM`, `BLE_PARAM_SYSTEM_DRIFT_*`).
- При смене Kp/Ki интеграл сбрасывается (защита от windup на устаревшем состоянии).
- Применяется только к `fill` — dSP-обработка остаётся на 48 кГц, без изменения
  конвейера.

## 6. Soft-clip лимитер (`soft_clip` в `usb_audio.c`)

C1-непрерывный пороговый сатуратор, без трансцендентных функций:

```
t = 0.85  (≈ −1.4 dBFS — линейная зона для всего полезного сигнала)
f(x) = x                                                    при |x| ≤ t
f(x) = sign(x)·(1 − (1−t)² / (|x| − 2t + 1))                при |x| > t
```

Производная в точке `t` равна 1 (C1-гладкость) → переход в насыщение неслышим,
нет резких нечётных гармоник (усталость слуха от жёсткого клипа в зоне 2–5 кГц).

## 7. Преобразования дБ ↔ линейный

| Куда | Формула | Место |
|---|---|---|
| dB → линейный | `10^(dB/20)` | UI `dbToLinear` (gain, master volume) |
| linear → dB | `20·log10(v)` | UI `linearToDb` |
| блочная громкость: dB → sqrt-linear | `A = 10^(dB/40)` (используется в Cookbook как √gain) | `calc_biquad` |

Границы UI: gain −72..+12 dB → линейный [~0.00025 .. 3.98]; на проводе допустимы
`0..10` (валидация `is_valid_linear_gain(_, 10.0)`).

## 8. Валидация значений с провода (диапазоны)

| Параметр | Диапазон | Ограничение |
|---|---|---|
| freq (EQ/XO) | 10..20000 Гц | `is_valid_freq`, `isfinite` |
| gain EQ | −30..+30 дБ | `is_valid_eq_gain_db` |
| Q | 0.01..40 | `is_valid_q` |
| линейный gain (input/output/global) | 0..10 | `is_valid_linear_gain` |
| routing gain | 0..1 | `is_valid_linear_gain` |
| delay | 0..960 сэмплов (10 мс @ 96 кГц) | до float→uint32 каста (фикс UB) |
| drift Kp/Ki | 0..100 | `is_valid_drift` |
| drift target | 0..1 | `is_valid_drift` |
| drift max_ppm | 0..100000 | `is_valid_drift` |
| filter_type | 0..7 | `≤ BLE_FILTER_ALL_PASS` |
| xo_type | 0..1 | Butterworth / Linkwitz-Riley |
| xo_slope | 1 / 2 / 4 | иначе → 1 (defence-in-depth) |

Bulk-путь зеркалит те же диапазоны (`dsp_param_apply_bulk`) + обязательные
`isfinite` по всем коэффициентам биквадов и гейнам (фикс H5).

## 9. CRC-32 (IEEE 802.3)

```
полином 0xEDB88320 (reflected), init 0xFFFFFFFF, final XOR 0xFFFFFFFF
crc-поле (header.crc32) при расчёте = 0
```

Реализации-зеркала: `crc32_ieee` (FW, `dsp_param_update.c`) ↔
`checksum.ts` (UI). Пересчёт на устройстве — только в снапшоте
(`dsp_param_refresh_crc_in_place`), никогда в активном буфере.
